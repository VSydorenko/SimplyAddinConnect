# Драйвер LabelPrinter — інструкція для 1С-розробника

Драйвер **принтера етикеток** (ZPL) через **spooler-RAW** (Windows-черга, USB/локальні) або
**TCP:9100** (мережеві). Клас компоненти в 1С — **`LabelPrinter`**; тип обладнання БПО —
**`LabelPrinter`**. Компонента реалізує **стандартний контракт «Библиотеки подключаемого
оборудования» (БПО)**, тип «Принтер этикеток»: увесь вхід/вихід — **XML** (UTF-8), результат методу —
**Булево**, деталі помилки забираєш через `ПолучитьОшибку`.

Спільні механізми (підключення DLL, кеш компоненти, логування, тест-контур) — у
[README.md](README.md); тут — специфіка саме цього драйвера.

> **Верстку етикетки робиш у самій 1С** (механізм БПО «Принтер этикеток»): 1С формує шаблон
> (`Formatting`) і дані (`Labels`) як XML-пакет `LabelsTable`, а компонента перетворює його на потік
> ZPL і доставляє на принтер в обхід GDI-друку вендорського драйвера. Компонента — **міст даних**,
> не редактор макета.

## 1. Реєстрація як «Подключаемое оборудование»

На відміну від ECR (де об'єкт створюють напряму), цей драйвер вбудовується в підсистему
**«Подключаемое оборудование»** типовою схемою БПО:

1. Підключити зовнішню компоненту з ZIP (див. [README §2](README.md)) — отримати `СимвольноеИмя`.
2. Створити об'єкт компоненти:
   ```bsl
   Драйвер = Новый("AddIn." + СимвольноеИмя + ".LabelPrinter");
   ```
3. У формі налаштувань обладнання підсистема БПО сама викликає системні методи в потрібному
   порядку: `ПолучитьРевизиюИнтерфейса` → `ПолучитьОписание` → `ПараметрыОборудования` (форма
   параметрів) → `ПодключитьОборудование` (повертає `ИдентификаторУстройства`) →
   `ИнициализацияПринтера` → `ПечатьЭтикеток`.

Тип обладнання, який віддає `ПолучитьОписание` у `DriverDescription`, — **`LabelPrinter`**
(`IntegrationComponent="false"`, `IsEmulator="false"`, версія — з `version.h`).

> Об'єкт драйвера тримає стан підключень **у C++** (реєстр `DeviceID → канал`). Створюй його
> **один раз** і перевикористовуй між викликами (див. [README §2.3](README.md)); кожен
> `ИдентификаторУстройства` живе доти, доки не викличеш `ОтключитьОборудование`.

## 2. Довідник методів

Кожен метод має два імені: міжнародне (EN) і російське (RU) — виклик регістронезалежний. Усі
XML-параметри — рядки в кодуванні UTF-8. Функціональний результат методу — **Булево** (`Истина` —
успіх); при `Ложь` бери код+опис через `ПолучитьОшибку`.

### 2.1. ⚠️ OUT-параметри — передавай ЗМІННУ, не вираз

Кілька методів повертають значення через **вихідні (OUT) параметри** (напр. `ПодключитьОборудование`
кладе `ИдентификаторУстройства` в OUT). У такий параметр треба передати **оголошену змінну** — 1С
запише в неї результат. Передаси літерал/вираз/константу — значення нікуди не потрапить.

```bsl
Ид = "";                                        // ОГОЛОСИ змінну заздалегідь
Ок = Драйвер.ПодключитьОборудование(Ид, "LabelPrinter", ПараметрыXML);
// після виклику Ид містить ідентифікатор пристрою
```

### 2.2. Системні методи БПО

| Метод (EN / RU) | Параметри (IN/OUT) | Повертає | Опис |
|---|---|---|---|
| `GetInterfaceRevision` / `ПолучитьРевизиюИнтерфейса` | — | **Число** | Ревізія контракту БПО (зараз `4007`) |
| `GetDescription` / `ПолучитьОписание` | `DriverDescription`[OUT XML] | Булево | Паспорт драйвера (тип обладнання, версії, прапорці) |
| `GetLastError` / `ПолучитьОшибку` | `ErrorDescription`[OUT] | **Число** (код) | Остання помилка: LONG-код + опис в OUT (§5) |
| `EquipmentParameters` / `ПараметрыОборудования` | `EquipmentType`[IN], `TableParameters`[OUT XML] | Булево | Опис форми параметрів підключення |
| `ConnectEquipment` / `ПодключитьОборудование` | `DeviceID`[OUT], `EquipmentType`[IN], `ConnectionParameters`[IN XML] | Булево | Підключити пристрій; повертає `DeviceID` в OUT (§3) |
| `DisconnectEquipment` / `ОтключитьОборудование` | `DeviceID`[IN] | Булево | Відключити пристрій, звільнити канал і кеш формату |
| `EquipmentTest` / `ТестированиеОборудования` | `EquipmentType`[IN], `ConnectionParameters`[IN XML], `Description`[OUT], `DemoModeIsActivated`[OUT] | Булево | Перевірка параметрів підключення (демо-режим не використовується) |
| `SetApplicationInformation` / `УстановитьИнформациюПриложения` | `ApplicationSettings`[IN XML] | Булево | Приймається й ігнорується (ліцензійної логіки немає) |

### 2.3. Функціональні методи

| Метод (EN / RU) | Параметри (IN) | Повертає | Опис |
|---|---|---|---|
| `InitializePrinter` / `ИнициализацияПринтера` | `DeviceID` | Булево | Ініт-пакет ZPL: темність/швидкість/розмір/home з параметрів підключення |
| `PrintLabels` / `ПечатьЭтикеток` | `DeviceID`, `LabelsTable`[XML], `PackageStatus` | Булево | Друк пакета етикеток (§4). `PackageStatus` — `first`/`regular`/`last` |

> **Друк синхронний.** `ПечатьЭтикеток` повертається, коли байти **прийнято** транспортом (TCP: у
> сокет; spooler: завдання поставлено в чергу Windows) — це **не** підтвердження фізичного друку
> (для цього потрібен статус-полінг, поза обсягом v1). Семантику результату див. §4.4.

## 3. Параметри підключення — `ConnectionParameters` (XML)

`ПодключитьОборудование` (і `ТестированиеОборудования`) приймають параметри у форматі БПО:
кореневий `<Parameters>`, кожен параметр — `<Parameter Name="..." Value="..."/>`. Невідомі
параметри **ігноруються** (вимога БПО).

```xml
<?xml version="1.0"?>
<Parameters>
  <Parameter Name="TransportKind" Value="tcp"/>
  <Parameter Name="Host" Value="192.168.1.50"/>
  <Parameter Name="Port" Value="9100"/>
  <Parameter Name="DotsPerMm" Value="8"/>
  <Parameter Name="Darkness" Value="10"/>
  <Parameter Name="Speed" Value="4"/>
  <Parameter Name="LabelWidthMm" Value="60"/>
  <Parameter Name="LabelHeightMm" Value="40"/>
</Parameters>
```

| Параметр | Тип | Дефолт | Значення |
|---|---|---|---|
| `TransportKind` | Рядок | `spooler` | `spooler` — Windows-черга (USB/локальні); `tcp` — мережевий принтер |
| `PrinterName` | Рядок | — | **Тільки `spooler`:** точне ім'я черги Windows (як у «Пристрої та принтери») |
| `Host` | Рядок | — | **Тільки `tcp`:** IP/hostname принтера |
| `Port` | Число | `9100` | **Тільки `tcp`:** TCP-порт (RAW-друк — стандартно 9100) |
| `DotsPerMm` | Число | `8` | Роздільність: **8 / 12 / 24** точок на мм (≈203/300/600 dpi) |
| `Darkness` | Число | `10` | Темність термоголовки (`^MD`; діапазон залежить від моделі) |
| `Speed` | Число | `4` | Швидкість друку (`^PR`) |
| `LabelWidthMm` | Число | `0` | Ширина етикетки, мм (`^PW`; `0` — не задавати) |
| `LabelHeightMm` | Число | `0` | Висота/довжина етикетки, мм (`^LL`; `0` — не задавати) |
| `HomeXDots` / `HomeYDots` | Число | `0` | Зсув початку координат (`^LH`), у точках |

> **DotsPerMm задають у точках-на-мм, а не номінальний dpi** — «203 dpi» насправді ≈8 точок/мм;
> округлення до цілого dots/mm усуває похибку позиціювання. Постав `8` для 203-dpi принтера,
> `12` для 300-dpi, `24` для 600-dpi.

> **Увага:** `ПараметрыОборудования` описує форму налаштувань атрибутом `DefaultValue`, а
> `ConnectionParameters` при підключенні передає значення атрибутом **`Value`** — не переплутай.

## 4. Пакет друку — `LabelsTable` (XML) і `PackageStatus`

### 4.1. Структура пакета

`ПечатьЭтикеток` приймає XML із кореневим `<Data>`: опційна секція **`<Formatting>`** (шаблон:
геометрія й поля) + список **`<Labels>` / `<Label>` / `<Record>`** (дані екземплярів). Приклад
пакета `first`:

```xml
<?xml version="1.0"?>
<Data>
  <Formatting Width="60" Height="40">
    <Text    FieldName="Name" Left="1" Top="1"  Width="55" Height="10" FontName="Arial" FontSize="8"/>
    <Barcode FieldName="Bar"  Type="EAN13" Left="1" Top="22" Height="10" PrintHRI="true" FontSize="8"/>
  </Formatting>
  <Labels>
    <Label Quantity="2">
      <Record FieldName="Name" Value="Блокнот"/>
      <Record FieldName="Bar"  Value="4008110271538"/>
    </Label>
  </Labels>
</Data>
```

- **`<Formatting Width Height>`** — розмір етикетки в **мм**; діти — поля шаблону:
  - `<Text>` — текст (растеризується GDI+): `FontName`, `FontSize`, `FontStyle`, `Align`/`VAlign`,
    `Multiline`, рамка (`Border`/`BorderWidth`/`BorderStyle`).
  - `<Barcode>` — штрихкод (нативна ZPL-команда): `Type` (§4.5), `PrintHRI`, `FontSize` (кегль HRI),
    `CheckSymbol`.
  - `<Image>` — картинка (растеризується): значення — Base64.
  - `<UserData>` — службове поле-значення без візуалізації.
  - Геометрія полів: `Left`/`Top`/`Width`/`Height` у **мм**, `Orientation` (`0`/`90`/`180`/`270`).
- **`<Label Quantity="n">`** — екземпляр етикетки; `Quantity` → число копій (`^PQ`).
- **`<Record FieldName Value>`** — значення поля для цього екземпляра. **Відсутній атрибут `Value`
  ≠ порожній рядок:** якщо запису немає, береться значення за замовчуванням з `Formatting.Value`.

**Static vs dynamic поля:** поле з `Static="true"` бере спільне значення прямо з `Formatting`
(`Value` для тексту/картинки, `ValueBase64` для штрихкоду); динамічне поле бере значення з `Record`
відповідного екземпляра.

### 4.2. Значення штрихкоду

- **Динамічний** штрихкод (`Record.Value`) — **простий текст** цифр/символів (напр.
  `4008110271538`), НЕ Base64.
- **Статичний** штрихкод (`Formatting … ValueBase64`) — Base64-кодоване значення.
- `EAN13` приймає як 12, так і 13 цифр — 13-ту (контрольну) драйвер відкидає, принтер рахує сам.

### 4.3. `PackageStatus` — пакетність (state machine per-DeviceID)

БПО дозволяє слати велику серію етикеток кількома пакетами. `PackageStatus` — рядок:

| Значення | Коли | Поведінка драйвера |
|---|---|---|
| `first` | перший (або єдиний) пакет серії | **Обов'язково** несе `<Formatting>`; драйвер кешує шаблон і скидає попередній стан |
| `regular` | проміжний пакет | Використовує кешований `Formatting`; `<Formatting>` не потрібен |
| `last` | останній пакет серії | Друкує й **очищає кеш** шаблону |

- `regular`/`last` **без попереднього `first`** (немає активного кешу) → помилка `BAD_INPUT`.
- `first` **без секції `<Formatting>`** → помилка `BAD_INPUT`.
- Однопакетний друк: надішли `first` з `Formatting` і даними; за потреби закрий серію окремим `last`.
- `Disconnect` очищає кеш шаблону пристрою.

### 4.4. Семантика результату («прийнято», не «надруковано»)

При успіху `payload` (у логах драйвера; фасад повертає лише Булево + `ПолучитьОшибку` при відмові)
містить `acceptedInstances` (скільки екземплярів прийнято) і `acceptedCopies` (сума `Quantity`).
При відмові в середині пакета драйвер додає `failedIndex` (індекс екземпляра, що впав) і скільки
вже прийнято до нього. **«Прийнято» = байти віддано транспорту**, а не фізичний відбиток.

### 4.5. Символіки штрихкодів

**Підтримуються нативними ZPL-командами:**

| `Type` | ZPL | | `Type` | ZPL |
|---|---|---|---|---|
| `EAN13` | `^BE` | | `ITF14` | `^B2` |
| `EAN8` | `^B8` | | `QRCode` | `^BQ` |
| `Code128` | `^BC` | | `DataMatrix` | `^BX` |
| `EAN128` (GS1-128) | `^BC`+FNC1 | | `PDF417` | `^B7` |
| `Code39` | `^B3` | | `GS1DataBarExpandedStacked` | `^BR` |
| `Code93` | `^BA` | | | |

**Поворот штрихкодів працює:** `Orientation` `0/90/180/270` мапиться на ZPL-орієнтацію поля
`N/R/I/B`.

**Відкладено до v2 → `UNSUPPORTED_BARCODE`** (у v1 повертають помилку з описом):

- `EAN13Addon2`, `EAN13Addon5` (штрихкод-розширення add-on 2/5);
- UPC-розширення (`…Extension…`);
- `Code16K` (немає нативної команди в ZPL);
- будь-який інший `Type`, якого немає в таблиці підтримуваних.

> Растрового фолбеку для штрихкодів **немає** (GDI+ не кодує символіки коректно) — непідтримувана
> символіка завжди дає `UNSUPPORTED_BARCODE`, а не «намальований» неробочий код.

### 4.6. Обмеження повороту растрових полів

У v1 поворот реалізовано **лише для штрихкодів**. Для **растрових** полів (`<Text>`, `<Image>`)
`Orientation` має бути `0`; будь-яке інше значення → помилка **`RENDER_ERROR`**. Поворот
тексту/картинок заплановано на v2.

## 5. Помилки — `ПолучитьОшибку`

`ПолучитьОшибку(ОписаниеОшибки)` повертає **LONG-код** і кладе людиночитний опис у OUT-параметр:

- **`0`** — остання операція успішна;
- **`-1`** — помилка (машинні коди драйвера — рядкові, тож у LONG вони зводяться до `-1`; конкретика
  — у тексті опису).

Тому орієнтуйся на **опис** (OUT) — він містить і причину, і, де доречно, машинний код. Машинні
коди драйвера в описах/логах:

| Код | Значення |
|---|---|
| `NOT_CONNECTED` | Пристрій не підключено (немає такого `DeviceID`) |
| `BAD_INPUT` | Некоректний пакет: `first` без `Formatting`, `regular`/`last` без активного `first`, невалідний XML |
| `TRANSPORT_ERROR` | Помилка каналу: не відкрився / прийнято менше байтів, ніж надіслано (spooler-RAW чи TCP) |
| `UNSUPPORTED_BARCODE` | Символіку штрихкоду не підтримано (§4.5) |
| `RENDER_ERROR` | Помилка растеризації GDI+ (у т.ч. `Orientation≠0` для тексту/картинки, §4.6) |
| `BARCODE_TOO_WIDE` | Штрихкод не влазить у задану ширину поля з урахуванням quiet-zone |
| `EXCEPTION` | Виняток у драйвері (деталі — в описі + лозі) |

```bsl
Опис = "";
Ок = Драйвер.ПечатьЭтикеток(Ид, ТаблицаЭтикеток, "first");
Если НЕ Ок Тогда
    Код = Драйвер.ПолучитьОшибку(Опис);          // Код = -1 для рядкових машинних кодів
    Сообщить("Друк не вдався [" + Код + "]: " + Опис);
КонецЕсли;
```

## 6. Рецепти

### 6.1. Повний цикл: підключення → ініт → друк

```bsl
&НаКлиенте
Перем Драйвер;   // одна instance на форму
Перем ИдУстройства;

&НаКлиенте
Процедура Подключить(Команда)
    // Драйвер уже створено з підключеної компоненти (README §2)
    ПараметрыXML =
        "<?xml version=""1.0""?><Parameters>"
        + "<Parameter Name=""TransportKind"" Value=""tcp""/>"
        + "<Parameter Name=""Host"" Value=""192.168.1.50""/>"
        + "<Parameter Name=""Port"" Value=""9100""/>"
        + "<Parameter Name=""DotsPerMm"" Value=""8""/>"
        + "<Parameter Name=""LabelWidthMm"" Value=""60""/>"
        + "<Parameter Name=""LabelHeightMm"" Value=""40""/>"
        + "</Parameters>";

    ИдУстройства = "";                                   // OUT — оголоси змінну
    Если НЕ Драйвер.ПодключитьОборудование(ИдУстройства, "LabelPrinter", ПараметрыXML) Тогда
        Опис = ""; Драйвер.ПолучитьОшибку(Опис);
        Сообщить("Не підключився: " + Опис); Возврат;
    КонецЕсли;

    Драйвер.ИнициализацияПринтера(ИдУстройства);         // темність/швидкість/розмір
КонецПроцедуры
```

### 6.2. Друк одного пакета

```bsl
&НаКлиенте
Процедура Друкувати(Команда)
    ТаблицаЭтикеток =
        "<?xml version=""1.0""?><Data>"
        + "<Formatting Width=""60"" Height=""40"">"
        + "<Text FieldName=""Name"" Left=""1"" Top=""1"" Width=""55"" Height=""10"" FontName=""Arial"" FontSize=""8""/>"
        + "<Barcode FieldName=""Bar"" Type=""EAN13"" Left=""1"" Top=""22"" Height=""10"" PrintHRI=""true"" FontSize=""8""/>"
        + "</Formatting>"
        + "<Labels><Label Quantity=""2"">"
        + "<Record FieldName=""Name"" Value=""Блокнот""/>"
        + "<Record FieldName=""Bar"" Value=""4008110271538""/>"
        + "</Label></Labels></Data>";

    Если НЕ Драйвер.ПечатьЭтикеток(ИдУстройства, ТаблицаЭтикеток, "first") Тогда
        Опис = ""; Драйвер.ПолучитьОшибку(Опис);
        Сообщить("Друк не вдався: " + Опис);
    КонецЕсли;
КонецПроцедуры
```

### 6.3. Серія кількома пакетами

```bsl
Драйвер.ПечатьЭтикеток(Ид, ПакетXML_first,   "first");    // несе <Formatting>
Драйвер.ПечатьЭтикеток(Ид, ПакетXML_regular, "regular");  // тільки <Labels>
Драйвер.ПечатьЭтикеток(Ид, ПакетXML_last,    "last");     // друкує + чистить кеш формату
```

### 6.4. Друк на USB/локальний принтер (spooler-RAW)

```bsl
ПараметрыXML =
    "<?xml version=""1.0""?><Parameters>"
    + "<Parameter Name=""TransportKind"" Value=""spooler""/>"
    + "<Parameter Name=""PrinterName"" Value=""Zebra ZD220 (Generic / Text Only)""/>"
    + "<Parameter Name=""DotsPerMm"" Value=""8""/>"
    + "</Parameters>";
```

## 7. Деплой: черга Windows має бути «Generic / Text Only»

Транспорт `spooler` шле **сирий ZPL** у Windows-чергу (RAW datatype), навмисне **обходячи
GDI-рендер вендорського драйвера**. Якщо чергу створено на «розумному» вендорському драйвері, він
може перехопити/переформатувати потік — і замість етикетки вийде сміття або порожнеча.

**Найнадійніший універсальний варіант — створити чергу Windows на драйвері «Generic / Text
Only»**, спрямовану на USB/LPT/COM-порт принтера, і в `PrinterName` вказати саме її ім'я. Тоді
spooler передає байти ZPL на пристрій без змін. (Мережеві принтери через `tcp`:9100 цієї проблеми
не мають — там немає драйвера в тракті.)

## 8. Тестування проти емулятора (без принтера)

Компонента постачається зі **standalone-емулятором** ZPL-принтера — тестуй прикладний код без заліза.

1. **Зібрати** тестові EXE: `powershell -File build_project.ps1 -WithTests` → у `bin/Release`
   з'являться `label_printer_emulator.exe` (x86) і `label_printer_emulator_x64.exe`.
2. **Запустити** емулятор (default порт **9100**):
   ```
   bin\Release\label_printer_emulator_x64.exe 9100
   ```
   Він слухає `127.0.0.1:9100`, накопичує вхідний ZPL-потік і друкує нові байти в консоль
   (Ctrl-C — вихід).
3. **У 1С** підключити компоненту й спрямувати драйвер на емулятор через `tcp`:
   `TransportKind=tcp`, `Host=127.0.0.1`, `Port=9100`.
4. **Викликати** `ИнициализацияПринтера`/`ПечатьЭтикеток` — емулятор виведе згенерований ZPL.

**Візуалізація:** скопіюй ZPL із консолі емулятора в онлайн-переглядач **Labelary**
(labelary.com) — він відрендерить етикетку як на реальному принтері (штрихкоди, текст, `^GF`-растр),
щоб звірити верстку без заліза.

> **Перед перезбіркою** (`build_project.ps1`) **закрий емулятор** — інакше лінкер не перезапише
> запущений `label_printer_emulator_*.exe` (`LNK1104`), і збірка впаде.

> Для CI/розробника є автоматичні гейти без 1С: `label_printer_selftest` (юніт: XML→ZPL, `^GF`,
> batch state machine, символіки) і `label_native_host` (компонента через головну DLL, БПО-методи з
> реальним XML проти емулятора) — див. [AGENTS.md](../../AGENTS.md) «Тести».

## 9. Типові помилки й рішення

| Симптом | Причина / рішення |
|---|---|
| `ПодключитьОборудование` = `Ложь` | Невірний `Host:Port`/`PrinterName`, або принтер/емулятор не слухає |
| `ИдУстройства` порожній після підключення | В OUT-параметр передали вираз/константу замість змінної (§2.1) |
| Опис `BAD_INPUT` | `first` без `<Formatting>`, або `regular`/`last` без попереднього `first` (§4.3) |
| Опис `UNSUPPORTED_BARCODE` | Символіка відкладена/невідома (add-on/UPC-extension/Code16K та ін. — §4.5) |
| Опис `RENDER_ERROR` | Зокрема `Orientation≠0` для `<Text>`/`<Image>` — поворот растру в v1 не підтримано (§4.6) |
| Опис `TRANSPORT_ERROR` | Канал не відкрився або прийняв менше байтів; для spooler — перевір чергу (§7) |
| На spooler виходить сміття/порожнеча | Черга на вендорському драйвері переформатовує RAW — переведи на «Generic / Text Only» (§7) |
| Друк «пройшов», а етикетки немає | Результат = **прийнято** транспортом, не фізичний друк (§4.4); перевір носій/калібрування принтера |
| 1С вантажить стару версію | Кеш компоненти — див. [README §2.2](README.md) |
