# Драйвер LabelPrinter — інструкція для 1С-розробника

Драйвер **принтера етикеток** (ZPL) через **spooler-RAW** (Windows-черга, USB/локальні) або
**TCP:9100** (мережеві). Клас компоненти в 1С — **`LabelPrinter`**; тип обладнання БПО —
**`LabelPrinter`** (у переліку конфігурації — `ПринтерЭтикеток`). Компонента реалізує
**стандартний контракт «Библиотеки подключаемого оборудования» (БПО)**, тип «Принтер этикеток»:
параметри підключення передаються **поодинці** через `УстановитьПараметр`, пакет друку — **XML**
(UTF-8), результат методу — **Булево**, деталі помилки забираєш через `ПолучитьОшибку`.

Спільні механізми (підключення DLL, кеш компоненти, логування, тест-контур) — у
[README.md](README.md); тут — специфіка саме цього драйвера.

> **Верстку етикетки робиш у самій 1С** (механізм БПО «Принтер этикеток»): 1С формує шаблон
> (`Formatting`) і дані (`Labels`) як XML-пакет `LabelsTable`, а компонента перетворює його на потік
> ZPL і доставляє на принтер в обхід GDI-друку вендорського драйвера. Компонента — **міст даних**,
> не редактор макета.

## 1. Реєстрація як «Подключаемое оборудование»

На відміну від ECR (де об'єкт створюють напряму), цей драйвер вбудовується в підсистему
**«Подключаемое оборудование»** типовою схемою БПО:

1. Підключити зовнішню компоненту з ZIP (див. [README §2](README.md)) — отримати `СимвольноеИмя`.
2. Створити об'єкт компоненти:
   ```bsl
   Драйвер = Новый("AddIn." + СимвольноеИмя + ".LabelPrinter");
   ```
3. У формі налаштувань обладнання підсистема БПО сама викликає системні методи в потрібному
   порядку:

```
ПолучитьРевизиюИнтерфейса()                       → 3004
ПолучитьОписание(ОписаниеДрайвера[OUT])           паспорт драйвера
ПолучитьПараметры(ПараметрыДрайвера[OUT])         опис форми налаштувань
УстановитьПараметр("EquipmentType", "ПринтерЭтикеток")
УстановитьПараметр(<ім'я>, <значення>) × N        усі параметри підключення
Подключить(ИДУстройства[OUT])                     безпараметровий, крім OUT
ИнициализацияПринтера(ИДУстройства)
ПечатьЭтикеток(ИДУстройства, ДанныеДляВыгрузки, СтатусПакета)
```

**Послідовність жорстка й безальтернативна:** `EquipmentType` і параметри приходять **окремими
викликами ДО** `Подключить`, а не одним XML-пакетом. `ТестУстройства` форма кличе **одразу після
`УстановитьПараметр`, без `Подключить`** — тож параметри перед тестом теж треба поставити.

Тип обладнання, який віддає `ПолучитьОписание` у `DriverDescription`, — **`LabelPrinter`**
(`IntegrationComponent="false"`, `IsEmulator="false"`, версія — з `version.h`). На вході
`УстановитьПараметр("EquipmentType", …)` драйвер приймає **і** `ПринтерЭтикеток` (саме це шле 1С —
ім'я значення переліку), **і** `LabelPrinter`.

> ⚠️ **ОДИН об'єкт = ОДИН принтер.** Параметри накопичуються **на об'єкті** до `Подключить`, тож
> параметри другого принтера затерли б перший. Треба два принтери — створи **два об'єкти**
> компоненти. Об'єкт тримає стан підключення **у C++**: створюй його **один раз** і
> перевикористовуй між викликами (див. [README §2.3](README.md)); отриманий `ИДУстройства` живе
> доти, доки не викличеш `Отключить`.

> Повний контракт БПО (усі системні методи, три формати XML, доказ по обох конфігураціях) —
> [docs/architecture/bpo-contract.md](../architecture/bpo-contract.md).
> **Історія:** до 2026-09-01 драйвер реєстрував **довгі** імена за документом ІТС
> (`ПодключитьОборудование`, `ПараметрыОборудования`, `ТестированиеОборудования`) і через штатну
> підсистему не підхоплювався взагалі. Якщо бачиш такий виклик у старому прикладному коді —
> це вже не працює, переведи на короткі імена з §2.2.

## 2. Довідник методів

Кожен метод має два імені: міжнародне (EN) і російське (RU) — виклик регістронезалежний. Усі
XML-параметри — рядки в кодуванні UTF-8. Функціональний результат методу — **Булево** (`Истина` —
успіх); при `Ложь` бери код+опис через `ПолучитьОшибку`.

### 2.1. ⚠️ OUT-параметри — передавай ЗМІННУ, не вираз

Кілька методів повертають значення через **вихідні (OUT) параметри** (напр. `Подключить`
кладе `ИДУстройства` в OUT). У такий параметр треба передати **оголошену змінну** — 1С
запише в неї результат. Передаси літерал/вираз/константу — значення нікуди не потрапить.

```bsl
ИДУстройства = "";                              // ОГОЛОСИ змінну заздалегідь
Ок = ОбъектДрайвераLP.Подключить(ИДУстройства);
// після виклику ИДУстройства містить ідентифікатор пристрою
```

### 2.2. Системні методи БПО

Це **той самий** набір, що й у решти драйверів обладнання проєкту — його реєструє спільна база
фасадів. Повна звірка з конфігурацією — [bpo-contract.md §2](../architecture/bpo-contract.md).

| Метод (EN / RU) | Параметри (IN/OUT) | Повертає | Опис |
|---|---|---|---|
| `GetInterfaceRevision` / `ПолучитьРевизиюИнтерфейса` | — | **Число** | Ревізія контракту БПО — **`3004`** |
| `GetVersionNumber` / `ПолучитьНомерВерсии` | — | Рядок | Версія компоненти (`version.h`) |
| `GetDescription` / `ПолучитьОписание` | `ОписаниеДрайвера`[OUT XML] | Булево | Паспорт драйвера (тип обладнання, версії, прапорці) |
| `GetParameters` / `ПолучитьПараметры` | `ПараметрыДрайвера`[OUT XML] | Булево | Опис **форми налаштувань** (§3) |
| `SetParameter` / `УстановитьПараметр` | `ИмяПараметра`[IN], `ЗначениеПараметра`[IN] | Булево | Один параметр підключення; кличеться N разів ДО `Подключить` (§3) |
| `Connect` / `Подключить` | `ИДУстройства`[OUT] | Булево | Підключити пристрій із накопичених параметрів |
| `Disconnect` / `Отключить` | `ИДУстройства`[IN] | Булево | Відключити пристрій, звільнити канал і кеш формату |
| `EquipmentTest` / `ТестУстройства` | `РезультатТеста`[OUT], `АктивированДемоРежим`[OUT] | Булево | Перевірка параметрів + **реальна досяжність** принтера (§6.6) |
| `GetLastError` / `ПолучитьОшибку` | `ОписаниеОшибки`[OUT] | **Число** (код) | Остання помилка: LONG-код + опис в OUT (§5) |
| `GetAdditionalActions` / `ПолучитьДополнительныеДействия` | `ДополнительныеДействия`[OUT XML] | Булево | Порожній набір — додаткових дій принтер не має |
| `DoAdditionalAction` / `ВыполнитьДополнительноеДействие` | `ИмяДействия`[IN] | Булево | Завжди `Ложь` («невідома дія») |

> ⚠️ **Старих довгих імен більше немає.** `ПодключитьОборудование`, `ПараметрыОборудования`,
> `ТестированиеОборудования`, `ОтключитьОборудование`, `УстановитьИнформациюПриложения` прибрано
> 2026-09-01: 1С їх не кличе в жодній конфігурації, а `УстановитьИнформациюПриложения` не кличе
> взагалі ніхто. Виклик такого імені тепер дасть «Метод объекта не обнаружен».

### 2.3. Функціональні методи

| Метод (EN / RU) | Параметри (IN) | Повертає | Опис |
|---|---|---|---|
| `InitializePrinter` / `ИнициализацияПринтера` | `ИДУстройства` | Булево | Ініт-пакет ZPL: темність/швидкість/розмір/home з параметрів підключення |
| `PrintLabels` / `ПечатьЭтикеток` | `ИДУстройства`, `ДанныеДляВыгрузки`[XML], `СтатусПакета` | Булево | Друк пакета етикеток (§4). `СтатусПакета` — `first`/`regular`/`last` |

> **Друк синхронний.** `ПечатьЭтикеток` повертається, коли байти **прийнято** транспортом (TCP: у
> сокет; spooler: завдання поставлено в чергу Windows) — це **не** підтвердження фізичного друку
> (для цього потрібен статус-полінг, поза обсягом v1). Семантику результату див. §4.4.

## 3. Параметри підключення — `УстановитьПараметр(Имя, Значение)`

Параметри приходять **поодинці, ДО** `Подключить` — окремим викликом на кожен. Першим —
`EquipmentType`. Невідомі імена **ігноруються** (вимога БПО), тож зайвий параметр помилки не дасть.

```bsl
Драйвер.УстановитьПараметр("EquipmentType", "ПринтерЭтикеток");
Драйвер.УстановитьПараметр("TransportKind", "tcp");
Драйвер.УстановитьПараметр("Host", "192.168.1.50");
Драйвер.УстановитьПараметр("Port", 9100);          // ЧИСЛОМ, не рядком
Драйвер.УстановитьПараметр("DotsPerMm", 8);
Драйвер.УстановитьПараметр("Darkness", 10);
Драйвер.УстановитьПараметр("Speed", 4);
```

| Параметр | Тип значення | Дефолт | Значення |
|---|---|---|---|
| `EquipmentType` | Рядок | — | `ПринтерЭтикеток` (так шле 1С) або `LabelPrinter`; інше → `Ложь` |
| `TransportKind` | Рядок | `spooler` | `spooler` — Windows-черга (USB/локальні); `tcp` — мережевий принтер |
| `PrinterName` | Рядок | — | **Тільки `spooler`, обов'язковий:** точне ім'я черги Windows (як у «Пристрої та принтери») |
| `Host` | Рядок | — | **Тільки `tcp`, обов'язковий:** IP/hostname принтера |
| `Port` | **Число** | `9100` | **Тільки `tcp`:** TCP-порт (RAW-друк — стандартно 9100) |
| `DotsPerMm` | **Число** | `8` | Роздільність: **8 / 12 / 24** точок на мм (≈203/300/600 dpi) |
| `Darkness` | **Число** | `10` | Темність термоголовки (`^MD`; діапазон залежить від моделі) |
| `Speed` | **Число** | `4` | Швидкість друку (`^PR`) |
| `LabelWidthMm` | **Число** | `0` | Ширина етикетки, мм (`^PW`; `0` — не задавати) |
| `LabelHeightMm` | **Число** | `0` | Висота/довжина етикетки, мм (`^LL`; `0` — не задавати) |
| `HomeXDots` / `HomeYDots` | **Число** | `0` | Зсув початку координат (`^LH`), у точках; у формі налаштувань їх немає — лише програмно |

> **Числові параметри передавай ЧИСЛОМ** (`Число(...)`, а не рядком): форма налаштувань БПО
> оголошує їх як `Number` і шле 1С саме числом. Драйвер приймає обидва варіанти — конвертація
> толерантна, — але дзеркалити реальний виклик підсистеми надійніше.

> **Не заповнив обов'язковий параметр транспорту** (`Host` для `tcp`, `PrinterName` для `spooler`)
> — `Подключить`/`ТестУстройства` віддадуть `Ложь` із кодом **`12` (`BAD_INPUT`)** і прямою вказівкою,
> якого поля бракує, а не туманним «принтер недоступний».

> **DotsPerMm задають у точках-на-мм, а не номінальний dpi** — «203 dpi» насправді ≈8 точок/мм;
> округлення до цілого dots/mm усуває похибку позиціювання. Постав `8` для 203-dpi принтера,
> `12` для 300-dpi, `24` для 600-dpi.

> **Історична форма — XML-пакет.** Документ ІТС описує передачу параметрів одним пласким
> `<Parameters><Parameter Name="…" Value="…"/></Parameters>`; імена й семантика параметрів там ті
> самі, що в таблиці вище. Драйвер її **не приймає** — 1С її не шле, і метод, який її брав, прибрано
> 2026-09-01. Згадка лишена, бо ця форма трапляється в документації ІТС і в старих прикладах.

> **Формат опису форми налаштувань суворий** (виправлено 2026-08-31; віддає `ПолучитьПараметры`).
> Форма БПО (`Catalogs.ПодключаемоеОборудование`, `ФормаНастройки`) читає XML послідовно й входить
> у розбір ЛИШЕ за кореневим вузлом **`Settings`**; корінь `Parameters` цю умову не проходить,
> і форма мовчки лишається **без жодного поля**. Тип параметра береться з атрибута
> **`TypeValue`** (`String`/`Number`/`Boolean`), а не `Type`. Розпізнаються `Page@Caption`,
> `Group@Caption`, `Parameter@Name/@Caption/@TypeValue/@DefaultValue/@Description/@FieldFormat/
> @ReadOnly` і вкладений `ChoiceList/Item@Value` (текст вузла — представлення); решта атрибутів
> ігнорується. До виправлення драйвер віддавав корінь `Parameters` з атрибутом `Type` —
> тобто форма налаштувань не працювала. Джерела: ІТС «Разработка драйвера для подключения
> оборудования локально к устройству пользователя» (розділ `ТаблицаПараметров`) + розбір
> парсера у конфігурації УНФ.

## 4. Пакет друку — `LabelsTable` (XML) і `PackageStatus`

### 4.1. Структура пакета

`ПечатьЭтикеток` приймає XML із кореневим `<Data>`: опційна секція **`<Formatting>`** (шаблон:
геометрія й поля) + список **`<Labels>` / `<Label>` / `<Record>`** (дані екземплярів). Приклад
пакета `first`:

```xml
<?xml version="1.0"?>
<Data>
  <Formatting Width="60" Height="40">
    <Text    FieldName="Name" Left="1" Top="1"  Width="55" Height="10" FontName="Arial" FontSize="8"/>
    <Barcode FieldName="Bar"  Type="EAN13" Left="1" Top="22" Height="10" PrintHRI="true" FontSize="8"/>
  </Formatting>
  <Labels>
    <Label Quantity="2">
      <Record FieldName="Name" Value="Блокнот"/>
      <Record FieldName="Bar"  Value="4008110271538"/>
    </Label>
  </Labels>
</Data>
```

- **`<Formatting Width Height>`** — розмір етикетки в **мм**; діти — поля шаблону:
  - `<Text>` — текст (растеризується GDI+): `FontName`, `FontSize`, `FontStyle`, `Align`/`VAlign`,
    `Multiline`, рамка (`Border`/`BorderWidth`/`BorderStyle`).
  - `<Barcode>` — штрихкод (нативна ZPL-команда): `Type` (§4.5), `PrintHRI`, `FontSize` (кегль HRI),
    `CheckSymbol`.
  - `<Image>` — картинка (растеризується): значення — Base64.
  - `<UserData>` — службове поле-значення без візуалізації.
  - Геометрія полів: `Left`/`Top`/`Width`/`Height` у **мм**, `Orientation` (`0`/`90`/`180`/`270`).
- **`<Label Quantity="n">`** — екземпляр етикетки; `Quantity` → число копій (`^PQ`).
- **`<Record FieldName Value>`** — значення поля для цього екземпляра. **Відсутній атрибут `Value`
  ≠ порожній рядок:** якщо запису немає, береться значення за замовчуванням з `Formatting.Value`.

**Static vs dynamic поля:** поле з `Static="true"` бере спільне значення прямо з `Formatting`
(`Value` для тексту/картинки, `ValueBase64` для штрихкоду); динамічне поле бере значення з `Record`
відповідного екземпляра.

### 4.2. Значення штрихкоду

- **Динамічний** штрихкод (`Record.Value`) — **простий текст** цифр/символів (напр.
  `4008110271538`), НЕ Base64.
- **Статичний** штрихкод (`Formatting … ValueBase64`) — Base64-кодоване значення.
- `EAN13` приймає як 12, так і 13 цифр — 13-ту (контрольну) драйвер відкидає, принтер рахує сам.

### 4.3. `PackageStatus` — пакетність (state machine per-DeviceID)

БПО дозволяє слати велику серію етикеток кількома пакетами. `PackageStatus` — рядок:

| Значення | Коли | Поведінка драйвера |
|---|---|---|
| `first` | перший (або єдиний) пакет серії | **Обов'язково** несе `<Formatting>`; драйвер кешує шаблон і скидає попередній стан |
| `regular` | проміжний пакет | Використовує кешований `Formatting`; `<Formatting>` не потрібен |
| `last` | останній пакет серії | Друкує й **очищає кеш** шаблону |

- `regular`/`last` **без попереднього `first`** (немає активного кешу) → помилка `BAD_INPUT`.
- `first` **без секції `<Formatting>`** → помилка `BAD_INPUT`.
- Однопакетний друк: надішли `first` з `Formatting` і даними; за потреби закрий серію окремим `last`.
- `Disconnect` очищає кеш шаблону пристрою.

### 4.4. Семантика результату («прийнято», не «надруковано»)

При успіху `payload` (у логах драйвера; фасад повертає лише Булево + `ПолучитьОшибку` при відмові)
містить `acceptedInstances` (скільки екземплярів прийнято) і `acceptedCopies` (сума `Quantity`).
При відмові в середині пакета драйвер додає `failedIndex` (індекс екземпляра, що впав) і скільки
вже прийнято до нього. **«Прийнято» = байти віддано транспорту**, а не фізичний відбиток.

### 4.5. Символіки штрихкодів

**Підтримуються нативними ZPL-командами:**

| `Type` | ZPL | | `Type` | ZPL |
|---|---|---|---|---|
| `EAN13` | `^BE` | | `ITF14` | `^B2` |
| `EAN8` | `^B8` | | `QRCode` | `^BQ` |
| `Code128` | `^BC` | | `DataMatrix` | `^BX` |
| `EAN128` (GS1-128) | `^BC`+FNC1 | | `PDF417` | `^B7` |
| `Code39` | `^B3` | | `GS1DataBarExpandedStacked` | `^BR` |
| `Code93` | `^BA` | | | |

**Поворот штрихкодів працює:** `Orientation` `0/90/180/270` мапиться на ZPL-орієнтацію поля
`N/R/I/B`.

**Відкладено до v2 → `UNSUPPORTED_BARCODE`** (у v1 повертають помилку з описом):

- `EAN13Addon2`, `EAN13Addon5` (штрихкод-розширення add-on 2/5);
- UPC-розширення (`…Extension…`);
- `Code16K` (немає нативної команди в ZPL);
- будь-який інший `Type`, якого немає в таблиці підтримуваних.

> Растрового фолбеку для штрихкодів **немає** (GDI+ не кодує символіки коректно) — непідтримувана
> символіка завжди дає `UNSUPPORTED_BARCODE`, а не «намальований» неробочий код.

### 4.6. Обмеження повороту растрових полів

У v1 поворот реалізовано **лише для штрихкодів**. Для **растрових** полів (`<Text>`, `<Image>`)
`Orientation` має бути `0`; будь-яке інше значення → помилка **`RENDER_ERROR`**. Поворот
тексту/картинок заплановано на v2.

## 5. Помилки — `ПолучитьОшибку`

`ПолучитьОшибку(ОписаниеОшибки)` повертає **числовий код** останньої операції й кладе
людиночитний опис у OUT-параметр. `0` — успіх; будь-що інше — помилка.

⚠️ **Коди змінилися 2026-09-01.** Раніше в принтера була **власна** нумерація `1..7`; тепер
таксономія **єдина на всю компоненту** — ті самі числа означають те саме в еквайрингових фасадах
і в принтері. Якщо прикладний код галузиться на старих числах — перевір його.

| Код | Машинний код | Значення |
|---|---|---|
| `0` | `OK` | Остання операція успішна |
| `1` | `NOT_CONNECTED` | Пристрій не підключено (немає такого `ИДУстройства`) |
| `11` | `EXCEPTION` | Виняток у драйвері (деталі — в описі + лозі) |
| `12` | `BAD_INPUT` | Некоректний вхід: не заповнено `Host`/`PrinterName`, `first` без `Formatting`, `regular`/`last` без активного `first`, невалідний Base64 static-штрихкоду |
| `13` | `TRANSPORT_ERROR` | Помилка каналу: не відкрився / прийнято менше байтів, ніж надіслано (spooler-RAW чи TCP) |
| `14` | `UNSUPPORTED_BARCODE` | Символіку штрихкоду не підтримано (§4.5) |
| `15` | `BARCODE_TOO_WIDE` | Штрихкод не влазить у задану ширину поля з урахуванням quiet-zone |
| `16` | `RENDER_ERROR` | Помилка растеризації GDI+ (у т.ч. `Orientation≠0` для тексту/картинки, §4.6) |
| `-1` | — | Помилка рівня фасаду: виняток у системному методі, невідомий код |

Числа `2..10` у принтера не трапляються — вони належать еквайринговій частині спільної таксономії
(повна таблиця — [bpo-contract.md §4.3](../architecture/bpo-contract.md)).

Опис (OUT) завжди містить людиночитну причину — показуй саме його; числовий код зручний для
галуження логіки.

```bsl
Опис = "";
Ок = ОбъектДрайвераLP.ПечатьЭтикеток(ИДУстройства, ТаблицаЭтикеток, "first");
Если НЕ Ок Тогда
    Код = ОбъектДрайвераLP.ПолучитьОшибку(Опис);   // напр. 12 (BAD_INPUT), 16 (RENDER_ERROR)
    Сообщить("Друк не вдався [" + Строка(Код) + "]: " + Опис);
КонецЕсли;
```

### 6.6. Тест устройства

`ТестУстройства` **реально відкриває канал** до принтера (TCP-конект або `OpenPrinter` на черзі) і
одразу закриває — **нічого не друкує**: ініт-пакет змінив би темність/швидкість/розмір, а
адміністратор, який тисне «Тест устройства», на це не підписувався. Підключеним бути не треба —
форма налаштувань кличе тест **одразу після `УстановитьПараметр`**, тому параметри ставимо тут же.
`РезультатТеста` несе людський опис цілі й вердикт (`tcp://127.0.0.1:9100 — доступно`);
`АктивированДемоРежим` завжди `Ложь` — демо-режиму драйвер не має.

```bsl
&НаКлиенте
Процедура ТестУстройстваLP(Команда)
    Если НЕ ОбъектLPГотов() Тогда Возврат; КонецЕсли;
    Попытка
        // Форма налаштувань БПО кличе ТестУстройства ОДРАЗУ після УстановитьПараметр,
        // без Подключить — тому параметри ставимо тут же.
        ОбъектДрайвераLP.УстановитьПараметр("EquipmentType", "ПринтерЭтикеток");
        ОбъектДрайвераLP.УстановитьПараметр("TransportKind", "tcp");
        ОбъектДрайвераLP.УстановитьПараметр("Host", СокрЛП(АдресПринтераLP));
        ОбъектДрайвераLP.УстановитьПараметр("Port", Число(СокрЛП(ПортПринтераLP)));

        РезультатТеста = "";
        ДемоРежим = Ложь;
        Успех = ОбъектДрайвераLP.ТестУстройства(РезультатТеста, ДемоРежим);
        ВывестиРезультатLP("ТестУстройства = " + Строка(Успех) + " | " + РезультатТеста
            + " | демо-режим: " + Строка(ДемоРежим) + ?(Успех, "", " | " + ПрочитатьОшибкуLP()));
    Исключение
        ВывестиРезультатLP("Помилка ТестУстройства: " + ОписаниеОшибки());
    КонецПопытки;
КонецПроцедуры
```

> Якщо принтер **уже підключений**, тест іде **тим самим** каналом, а не новою сесією: типовий
> ZPL-принтер другого з'єднання на `:9100` не приймає, і на справному пристрої ти побачив би
> `TRANSPORT_ERROR`.

## 7. Деплой: черга Windows має бути «Generic / Text Only»

Транспорт `spooler` шле **сирий ZPL** у Windows-чергу (RAW datatype), навмисне **обходячи
GDI-рендер вендорського драйвера**. Якщо чергу створено на «розумному» вендорському драйвері, він
може перехопити/переформатувати потік — і замість етикетки вийде сміття або порожнеча.

**Найнадійніший універсальний варіант — створити чергу Windows на драйвері «Generic / Text
Only»**, спрямовану на USB/LPT/COM-порт принтера, і в `PrinterName` вказати саме її ім'я. Тоді
spooler передає байти ZPL на пристрій без змін. (Мережеві принтери через `tcp`:9100 цієї проблеми
не мають — там немає драйвера в тракті.)

## 8. Тестування проти емулятора (без принтера)

Компонента постачається зі **standalone-емулятором** ZPL-принтера — тестуй прикладний код без заліза.

1. **Зібрати** тестові EXE: `powershell -File build_project.ps1 -WithTests` → у `bin/Release`
   з'являться `label_printer_emulator.exe` (x86) і `label_printer_emulator_x64.exe`.
2. **Запустити** емулятор (default порт **9100**):
   ```
   bin\Release\label_printer_emulator_x64.exe 9100
   ```
   Він слухає `127.0.0.1:9100`, накопичує вхідний ZPL-потік і друкує нові байти в консоль
   (Ctrl-C — вихід).
3. **У 1С** підключити компоненту й спрямувати драйвер на емулятор через `tcp`:
   `TransportKind=tcp`, `Host=127.0.0.1`, `Port=9100`.
4. **Викликати** `ИнициализацияПринтера`/`ПечатьЭтикеток` — емулятор виведе згенерований ZPL.

**Візуалізація:** скопіюй ZPL із консолі емулятора в онлайн-переглядач **Labelary**
(labelary.com) — він відрендерить етикетку як на реальному принтері (штрихкоди, текст, `^GF`-растр),
щоб звірити верстку без заліза.

> **Перед перезбіркою** (`build_project.ps1`) **закрий емулятор** — інакше лінкер не перезапише
> запущений `label_printer_emulator_*.exe` (`LNK1104`), і збірка впаде.

> Для CI/розробника є автоматичні гейти без 1С: `label_printer_selftest` (юніт: XML→ZPL, `^GF`,
> batch state machine, символіки) і `label_native_host` (компонента через головну DLL: імена
> контракту з §2.2, `УстановитьПараметр` → `Подключить` → `ТестУстройства` → друк проти емулятора)
> — див. [AGENTS.md](../../AGENTS.md) «Тести».

## 9. Типові помилки й рішення

| Симптом | Причина / рішення |
|---|---|
| «Метод объекта не обнаружен» на `ПодключитьОборудование`/`ПараметрыОборудования`/`ТестированиеОборудования` | Старі довгі імена прибрано 2026-09-01 — перейди на короткі імена контракту (§2.2) |

| Опис `BAD_INPUT` | `first` без `<Formatting>`, або `regular`/`last` без попереднього `first` (§4.3) |
| Опис `UNSUPPORTED_BARCODE` | Символіка відкладена/невідома (add-on/UPC-extension/Code16K та ін. — §4.5) |
| Опис `RENDER_ERROR` | Зокрема `Orientation≠0` для `<Text>`/`<Image>` — поворот растру в v1 не підтримано (§4.6) |
| Опис `TRANSPORT_ERROR` | Канал не відкрився або прийняв менше байтів; для spooler — перевір чергу (§7) |
| На spooler виходить сміття/порожнеча | Черга на вендорському драйвері переформатовує RAW — переведи на «Generic / Text Only» (§7) |
| Друк «пройшов», а етикетки немає | Результат = **прийнято** транспортом, не фізичний друк (§4.4); перевір носій/калібрування принтера |
| 1С вантажить стару версію | Кеш компоненти — див. [README §2.2](README.md) |
