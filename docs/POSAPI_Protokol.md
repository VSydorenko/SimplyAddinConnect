# 1 ЗАГАЛЬНА ІНФОРМАЦІЯ

Інтерфейс POSAPI призначений для глибокої інтеграції POS терміналів під управлінням USO v.3.100+ з програмними комплексами банківських систем, касових апаратів, електронних кіосків, автоматів самообслуговування та інших систем.

Для використання даного інтерфейсу необхідне підключення терміналу POS до відповідної системи через порт USB або по TCP/IP (мережа Ethernet).

Інтерфейс реалізований мовою програмування C і може постачатися у вигляді статичних та динамічних бібліотек. Це дозволяє інтегрувати його з більшістю промислових засобів розробки та популярних мов програмування.

На даний момент існують реалізації для платформ Win32/64 та Linux, при цьому бібліотеки можуть бути доступні в наступних варіантах постачання:

| Платформа | Файл          | Опис                                               |
|-----------|---------------|----------------------------------------------------|
| Win32/64  | POS.LIB       | Статична бібліотека MSVC-2015                      |
|           | POSAPI.DLL    | Динамічна бібліотека Windows                       |
|           | POSAPI2.DLL   | Спец. реалізація у вигляді об'єкта COM             |
|           | POSJAVA.DLL   | Спец. бібліотека для інтеграції з JAVA (через JNI) |
|           | POSNET.DLL    | Спец. бібліотека для інтеграції з.NET              |
| Linux     | LIBPOS.A      | Статична бібліотека GCC                            |
|           | LIBPOS.SO     | Динамічна бібліотека Linux                         |
|           | LIBPOSJAVA.SO | Спец. бібліотека для інтеграції з JAVA (через JNI) |

У комплект поставки також входить простий тестовий додаток, що базується на статичній бібліотеці. Воно дозволяє розробнику перевірити коректність підключення POS терміналу до ПК та його працездатність.

Вихідний код бібліотек не постачається і не розповсюджується, при необхідності їх складання під конкретний дистрибутив Linux або перенесення на іншу платформу уточніть наявність такої можливості та її умови у розробника.

Далі у цьому документі наводиться опис інтерфейсу POSAPI та особливостей його різних реалізацій, а також приклади їх використання.

# 2 ОПИС МЕТОДІВ ІНТЕРФЕЙСУ

У розділі описуються базові реалізації інтерфейсу, доступні у вигляді статичних і динамічних бібліотек. При використанні інших спеціалізованих реалізацій, синтаксис викликів може дещо відрізнятися (повна інформація про всі відмінності міститься у відповідних розділах), проте принципи їх використання повністю ідентичні базовим реалізаціям.

У найзагальнішому вигляді коректний алгоритм взаємодії з інтерфейсом може бути представлений у вигляді наступної послідовності викликів:

1. Відкриття сеансу взаємодії з терміналом за допомогою pos_open().
2. Налаштування параметрів запиту за допомогою pos_set().
3. Надсилання запиту за допомогою pos_send().
4. Зчитування відповіді за допомогою pos_receive().
5. Отримання параметрів відповіді за допомогою pos_get() або за допомогою пари методів pos_get_first() / pos_get_next(). Для отримання розмірів буферів, необхідних для зберігання значень параметрів можна скористатися методами pos_get_length()та pos_get_max_length().
6. Закриття сеансу взаємодії з терміналом за допомогою pos_close().

    Докладніше особливості використання методів інтерфейсу розкриваються нижче.

## 2.1 Відкриття сеансу: pos_open()

Цей метод призначений для відкриття сесії взаємодії з POS терміналом та отримання її дескриптора, тобто, для початку будь-якої операції. Після завершення операції відкриту сесію слід закрити за допомогою pos_close().

*Увага:*

- протягом кожної сесії може бути виконано не більше одного запиту проведення нової операції з допомогою pos_send();
- у кожний певний час може бути відкрито не більше однієї сесії взаємодії з певним POS терміналом;
- при порушенні даних правил поведінка бібліотеки та POS терміналу може бути непередбачуваною.

*Синтаксис:*

bool pos_open(POS_HANDLE \* *handle_p,* const char \* *name,* const char \* *log*)

| *Параметри:* |                                                                                                                                                                                                                                                                                                                               |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| *handle_p*   | Вказівник на дескриптор сесії, значення якого встановлюється бібліотекою у разі успішного завершення операції. Даний дескриптор повинен використовуватись при всіх наступних викликах методів у рамках сесії. У разі невдачі значення цього параметра встановлюється в *POS_NONE.*                                            |
| *name*       | Призначене операційною системою ім'я послідовного порту, до якого підключений термінал POS. Формат параметра при підключенні терміналу TCP/IP «*ip_address:port».*                                                                                                                                                            |
| *log*        | Файл журналу. Щоб вимкнути журнал викликів бібліотеки, слід встановити цей параметр у *NULL* або передати вказівник на порожній рядок. Щоб увімкнути журнал, слід передати вказівник на рядок з повним ім'ям файлу, коректним для даної платформи. У разі невдачі відкриття або створення файлу параметр буде проігнорований. |

*Значення, що повертається:*

Логічне, сигналізує про успішність виконання операції.

## 2.2 Закриття сеансу: pos_close()

Даний метод призначений для закриття сесії, відкритої раніше за допомогою pos_open(), та звільнення ресурсів системи та POS терміналу.

*Синтаксис:*

bool pos_close(POS_HANDLE \* *handle_p)* *Параметри:*

*handle_p* Вказівник на дескриптор відкритої сесії. У разі успішного завершення операції дескриптору надається значення *POS_NONE.*

*Значення, що повертається:*

Логічне, сигналізує про успішність виконання операції.

## 2.4 Зчитування відповіді: pos_receive()

Даний метод дозволяє зчитати відповідь POS терміналу на запит, надісланий раніше. ПЗ має викликати цей метод, якщо був успішно викликаний метод pos_send().

*Синтаксис:*

int pos_receive(POS_HANDLE *handle,* int *timeout*) *Параметри:*

*handle* Дескриптор сесії. *timeout* Час очікування відповіді в мілісекундах.

*Значення, що повертається:*

Цілочисельне, являє собою код відповіді POS терміналу на раніше надісланий запит. Допустимі значення:

| *RESP_TIMEOUT*    | - | Минув час очікування відповіді, метод слід викликати ще раз.                                                                                                                                                                                                                                                            |
|-------------------|---|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| *RESP_BREAK*      | - | Операція перервана POS терміналом.                                                                                                                                                                                                                                                                                      |
| *RESP_CONFIRM*    | - | Підтвердження успішного виконання цієї операції.                                                                                                                                                                                                                                                                        |
| *RESP_DECLINE*    | - | Запрошена операція відхилена терміналом чи процесинговим центром.                                                                                                                                                                                                                                                       |
| *RESP_MESSAGE*    | - | Повідомлення про поточний етап виконання POS терміналом операції. Інформація, що міститься в даній відповіді, може використовуватися касовим ПЗ для виведення на великий екран, з метою повідомлення касира або клієнта. Ця відповідь може                                                                              |
|                   |   | також ігноруватися викликаючим ПЗ. У разі отримання відповіді метод pos_receive() слід викликати ще раз.                                                                                                                                                                                                                |
| *RESP_IDENTIFIER* | - | Повідомлення про присвоєний ідентифікатор транзакції.                                                                                                                                                                                                                                                                   |
| *RESP_KEEPALIVE*  | - | Повідомлення про те, що термін термінал POS продовжує виконувати запит каси, і потрібен додатковий час для отримання відповіді. Це повідомлення POS термінал періодично посилає на касу в процесі виконання тривалих операцій. **У цій версії протоколу не підтримується. Зарезервований для подальшого використання.** |
| *RESP_WRONG_MAC*  | - | Неправильне поле MAC у команді, переданій терміналу.                                                                                                                                                                                                                                                                    |
|                   |   |                                                                                                                                                                                                                                                                                                                         |

Інші значення зарезервовані для майбутнього використання; у разі отримання ПЗ повинно перервати поточну операцію, надіславши запит *ACTION_BREAK.*

*Значення, що повертається:*

Логічне, сигналізує про успішність виконання операції.

**2.7 Зчитування всіх параметрів: pos_get_first() та**

## pos_get_next()

Дані методи призначені для послідовного зчитування імен та значень усіх параметрів, які повертаються POS терміналом в останньому виклику методу pos_receive(). Використовується шляхом попереднього виклику pos_get_first() і наступного циклічного виклику pos_get_next() до тих пір, поки його значення, що повертається, буде залишатися істинним.

*Синтаксис:*

bool pos_get_first (POS_HANDLE *handle,* char \* *param,* int *param_size,* char \* *val,* int *val_size)*

bool pos_get_next (POS_HANDLE *handle,* char \* *param,* int *param_size,* char \* *val,* int *val_size)* *Параметри:*

*handle* Дескриптор сесії.

*param* Буфер для зчитування імені параметра (C-рядки).

*param_size* Розмір буфера *param,* в байтах.

*val* Буфер для зчитування значення параметра (C-рядки).

*val_size* Розмір буфера *val* в байтах.

*Значення, що повертається:*

Логічне, сигналізує про успішність виконання операції.

Набір параметрів, що зчитуються даними методами, збігається з наведеним в описі методу pos_get(). Однак, у майбутньому список можливих параметрів може бути розширений, тому реалізація касового додатку повинна враховувати цей факт і коректно обробляти ситуації, коли ім'я зчитаного параметра невідоме.

## 2.8 Функції отримання розміру параметрів: pos_get_length () та pos_get_max_length ()

Ці функції дозволяють визначити необхідний розмір буфера для зберігання значень параметрів, які повертаються POS терміналом в останньому виклику методу pos_receive ().

*Синтаксис:*

int pos_get_length (POS_HANDLE handle, const char \*param) *Параметри:*

*handle* Дескриптор сесії.

*param* Ім'я параметра (С-рядок).

*Значення, що повертається:*

Повертає розмір буфера, необхідний збереження значення параметра *param.*

*Синтаксис:*

int pos_get_max_length (POS_HANDLE handle) *Параметри: handle* Дескриптор сесії.

*Значення, що повертається:*

Повертає розмір буфера, необхідний збереження максимально довгого зі значень всіх параметрів.

# 3 МЕХАНІЗМ ВІДНОВЛЕННЯ ПІСЛЯ ЗБОЇВ

Під час підготовки до проведення фінансової операції, відразу після зчитування картки, термінал передає на касу повідомлення RESP_IDENTIFIER. У цьому повідомленні передається параметр POS_TRANS_ID – унікальний ідентифікатор транзакції, наданий терміналом. Якщо повідомлення RESP_IDENTIFIER не буде успішно доставлено на касу, термінал фінансову операцію з процесингом не розпочне та поверне на касу RESP_BREAK.

При успішному завершенні фінансової операції термінал повертає на касу повідомлення RESP_CONFIRM і записує всю інформацію у внутрішній журнал транзакцій. У журналі транзакцій записуються лише успішні операції. Під час операції «Закриття дня» (ACTION_CLOSE_DAY) – журнал транзакцій очищається.

Таким чином, протягом робочого дня у журналі транзакцій зберігаються всі успішні фінансові операції. І у разі виникнення збою, каса може запросити статус будь-якої попередньої фінансової операції. Для цього каса має відкрити нову сесію (pos_open()) і надіслати на термінал запит ACTION_STATUS з параметром POS_TRANS_ID транзакції, стан якої потрібно визначити. Якщо транзакція з вказаним ідентифікатором буде знайдена в журналі транзакцій терміналу, на касу буде повернуто повідомлення RESP_CONFIRM з усіма параметрами успішно завершеної операції. Якщо транзакції з таким ідентифікатором немає, термінал поверне:

RESP_DECLINE - починаючи з версії ПЗ терміналу USO3.109r, при встановленні відповідного параметра терміналу;

RESP_BREAK в інших випадках.

**Примітка:** успішна операція скасування (ACTION_REVERSAL) заміняє фінансову операцію, яку вона скасовує. І статус операції (ACTION_STATUS) можна буде визначити лише для операції скасування.

# 4 АЛГОРИТМ УПРАВЛІННЯ РОЗМІРОМ ЗНИЖКИ ПІД ЧАС ПРОВЕДЕННЯ ОПЕРАЦІЇ «ОПЛАТА»

1. Каса передає на термінал запит проведення операції «Оплата» з параметром POS_REVISION_SIGN рівним 1 і сумою (POS\_ AMOUNT) без знижки.
2. Термінал пропонує касиру зчитати картку та висвічує отриману суму без знижки.
3. Отримавши номер картки та термін придатності, термінал передає на касу повідомлення RESP_IDENTIFIER з параметрами POS_TRANS_ID, POS_MSG_BREAK, POS_CARD_PAN, POS_CARD_EXPIRY,

    POS_CARD_LOYALTY_CODE, POS_CARD_TYPE.

4. Термінал висвічує повідомлення: «Очікування інформації» і чекає на запит від каси.
5. Каса, на підставі номера картки, розраховує знижку та передає на термінал запит ACTION_REVISION із параметром POS\_ AMOUNT – нова сума транзакції зі знижкою. Сума зі знижкою не повинна бути більшою за оригінальну суму операції, інакше термінал поверне RESP_BREAK.
6. Термінал проводить фінансову операцію.
7. Термінал повертає відповідь RESP_CONFIRM з наступними параметрами: POS_AMOUNT – авторизована сума операції зі знижкою, POS_ORIG_AMOUNT – сума операції без знижки (повертається лише в тому випадку, якщо сума була змінена). **Примітка:** Зміни в механізм корекції для операції «поповнення карти» ACTION_CASH_TO_CARD. Поле з початковою сумою POS\_ AMOUNT – опціональне. Воно обов’язково задається разом з сумою комісії POS_COMMISSION_AMOUNT, як параметри для запиту ACTION_REVISION.

    **5 ЗМІНА АЛГОРИТМУ ПРОВЕДЕННЯ ОПЕРАЦІЙ, ЯКІ ПОТРЕБУЮТЬ ПІДТВЕРДЖЕННЯ.**

8. Каса передає на термінал запит проведення операції з новим параметром POS_CONFIRM_SIGN рівним 1.
9. Термінал пропонує касиру зчитати картку. Далі термінал передає на касу повідомлення

RESP_IDENTIFIER з параметрами:

POS_TRANS_ID, POS_MSG_BREAK, POS_CARD_PAN, POS_CARD_EXPIRY, POS_CARD_LOYALTY_CODE, POS_CARD_TYPE.

1. Термінал висвічує повідомлення: «Очікування інформації від каси» і чекає на запит від каси.
2. Каса, на підставі отриманих даних, передає на термінал запит ACTION_CONFIRM з параметрами: POS_STATUS рівним 1 (confirm) або 0 (decline) та POS_DOCUMENT – (у випадку POS_STATUS рівним 1) з додатковими даними для друку.

7\. Термінал при POS_STATUS рівним 1 продовжує операцію, а у випадку POS_STATUS рівним 0 повертає RESP_BREAK.

#include <stdio.h>
#include "pos.h"

void print_response(POS_HANDLE handle)
{
    char par[20];
    char val[10240];

    if ( pos_get_first(handle, par, sizeof(par), val, sizeof(val)) )
    {
        do {
            printf("%s = \\"%s\\"\n", par, val);
        } while ( pos_get_next(handle, par, sizeof(par), val, sizeof(val)) );
    }
    printf("\\n");
}

int main()
{
    POS_HANDLE handle;
    int timeout = 180000;  // 3 min

    if ( !pos_open(&handle, "COM1", 0) )
        return -1;

    pos_set(handle, POS_AMOUNT, "100");  // 1.00
    pos_set(handle, POS_CURRENCY, "980"); // UAH

    if ( !pos_send(handle, ACTION_PAYMENT) ) {
        pos_close(&handle);
        return -2;
    }

    bool receive_loop = true;

    while ( receive_loop )
    {
        int resp = pos_receive(handle, timeout);
        switch(resp)
        {
            case RESP_TIMEOUT:
                printf("TIMEOUT!\\n");
                receive_loop = false;
                break;

            case RESP_BREAK:
                printf("BREAK!\\n");
                receive_loop = false;
                break;

            case RESP_CONFIRM:
                printf("CONFIRMED\\n");
                print_response(handle);
                receive_loop = false;
                break;

            case RESP_DECLINE:
                printf("DECLINED\\n");
                print_response(handle);
                receive_loop = false;
                break;

            case RESP_MESSAGE:
                printf("MESSAGE\\n");
                print_response(handle);
                break;

            case RESP_IDENTIFIER:
                printf("IDENTIFIER\\n");
                print_response(handle);
                break;
        }
    }

    pos_close(&handle);
    return 0;
}

**ДОДАТОК 1.**

1. Формат поля *POS_CARD_CTLS_INFO.* Це поле являє собою ASCII рядок, формат якого залежить від типу платіжної системи даної картки (Mastercard, Visa, …) і визначається значенням у 1-ій позиції: 1 – Mastercard, 2 – Visa.
    1. Формат поля для платіжної системи Mastercard. Визначається лише за наявності тега 9F6E на безконтактній карті:
        1. Позиції 2-3 - код пристрою (Device Type);
        2. Позиції 4-6 - код країни видавця карти (Country code);
        3. Позиції 7-14 - 8-ми значний номер токена, присутній тільки для значень кодів пристрою 14, 09, 16.
    2. Формат поля для платіжної системи Visa. Визначається лише за наявності тега 9F6E на безконтактній карті:
        1. Позиції 2-3 - форм-фактор платіжного пристрою (Device Form Factor). Можливі значення: 00 – безконтактна картка; 01 – безконтактна міні-картка; 02 - пристрій з безконтактним функціоналом (брелки, годинники, браслети); 03 – пристрій із безконтактним функціоналом та можливістю введення даних (смартфони з платіжним додатком).

Приклади сформованих полів.

"1" - карта Mastercard, тег 9F6E на безконтактній карті відсутня.

«100804» - карта Mastercard, код пристрою 00, код країни 804.

«11480412345678» - карта Mastercard, код пристрою 14, код країни 804, номер токена 12345678.

"200" - карта Visa, форм-фактор пристрою 00 - безконтактна карта.
