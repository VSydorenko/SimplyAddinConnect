# Виконання задачі через Workflow

**Обов'язковий аргумент — шлях до файлу задачі** (`$ARGUMENTS`; @-mention або plain
path). Якщо не передано — **ЗУПИНИСЬ** і попроси: «Вкажи файл задачі (шлях або
@-mention)». Якщо plain path — прочитай файл через Read.

Файл задачі:

$ARGUMENTS

## Директива

Виконай цю задачу **повністю та саме через `Workflow`** — і самі пункти задачі, і
верифікацію. Ти лишаєшся **головним оркестратором + валідатором**: розкидаєш робочі
кроки по субагентах воркфлоу й особисто валідуєш результат (робочі кроки НЕ соло).

- **Тіринг моделей — обов'язковий.** Кожному `agent()` явно став `model`+`effort`:
  recon/орієнтація/рутинна механіка → **Sonnet** (`low`/`medium` effort);
  архітектурно неоднозначне, синтез, verify → **Opus** (`high`+). Не лишай дорогий
  дефолт там, де вистачить дешевшого рівня.
- **Orientation-first.** Перша фаза — розвідка кодової бази: `Agent(subagent_type:
  "Explore")` + читання ключових файлів (`docs/architecture/`,
  `CMake/components.cmake`, відповідні `src/`), а вже тоді зміни.
- **Git-комітячі агенти на спільній гілці — ПОСЛІДОВНО**, не паралельно
  (гонки/clobber). Якщо потрібна паралельна правка файлів — `isolation: "worktree"`.

## Контекст проєкту

C++17 зовнішня компонента 1С під Windows; збірка — CMake + PowerShell. Канон і
конвенції — `AGENTS.md`; архітектура — `docs/architecture/`. Дотримуйся їх у КОЖНОМУ
агенті воркфлоу (передавай стислу витримку в промпт агента).

## Фази воркфлоу

1. **Орієнтація** — прочитати файл задачі + суміжні спеки, на які він посилається
   (`docs/architecture/`, `docs/*_Protokol.md`, `CMake/components.cmake`); розвідати
   радіус впливу змін по `src/` (Explore-агент, Grep/Glob).
2. **Імплементація** — виконати **ВСІ** пункти чеклісту задачі. Дисципліни (гайд для
   агентів воркфлоу):
   - `[CPP]` — код напряму, за конвенціями `AGENTS.md`: `pch.h` першим рядком у
     `.cpp`; логування лише через `REPORT_*` / `NEUTRAL_REPORT_*` (не `spdlog`
     напряму); після `REPORT_ERROR` → `return false`; конвертації рядків через
     `ServiceTools::Safe*`.
   - `[CMAKE]` — зміни збірки в `CMake/*.cmake` (джерело правди складу DLL —
     `components.cmake`); нову компоненту додати в `HEADER_FILES`/`SOURCE_FILES`,
     OBJECT-бібліотеку та `$<TARGET_OBJECTS:...>` фінальної SHARED-цілі.
   - `[UAPKI]` — правки, що зачіпають статичну збірку UAPKI, звіряй з
     `docs/architecture/uapki.md` і настановою `extern/uapki/doc/UAPKI-PM-2.0.16.md`; правки
     сабмодуля `extern/uapki` комітяться **всередині сабмодуля**.
   - `[TEST]` — тека `tests/` **існує** (окремі консольні exe, лінкуються НЕ в головну
     DLL, без `src/core/pch.h`); склад цілей і рівні гейта — `AGENTS.md` «Тести».
     Збірка з `-WithTests`, прогін — `run_tests.ps1 [x64|x86] [-NoUapki]`; не позначай
     тести робочими, поки гейт реально не зелений.
   - `[DOC]` — синхронізувати `docs/architecture/`, `AGENTS.md`, `CLAUDE.md`,
     `docs/*_Protokol.md`.
3. **Чистка легасі** — внести зміни так, щоб **не лишилось легасі, dead-code чи
   backward-compat старих механізмів**, де це реально можливо (не half-migration, не
   подвійні кодошляхи «старий+новий»).
4. **Синхронізація доків** — окремо пройтись по `docs/architecture/`, інструкціях
   (`AGENTS.md` / `CLAUDE.md`) і **виправити старі підходи на нові** відповідно до
   змін задачі (щоб канон не дрейфував). Команди/факти в доках мають лишатись
   звіреними з кодом.
5. **Верифікація (теж через воркфлоу)** — `Skill(code-review)` + за потреби fan-out
   субагентів по областях; перевір, що задача виконана **ПОВНІСТЮ** й відповідає
   поставленій задачі та специфікації; **дороби всі зауваження рев'ю**; фінальний
   гейт — **успішна збірка**:
   `powershell -ExecutionPolicy Bypass -File build_project.ps1` (додай `-WithUAPKI`,
   якщо задача зачіпає UAPKI) — обидві архітектури (x86+x64) у Release без помилок,
   ZIP зібрано. Якщо в задачі є тести й `tests/` існує — `run_tests.ps1` зелений.
6. **Відмітки та статус** — познач виконані пункти `[X]` у файлі задачі (лише реально
   зроблене) і **онови суміжні задачі** в `docs/tasks/` актуальним статусом.

## Валідація та критерій успіху

- Max 2 retry на фейл збірки в межах агента; далі — глибша розвідка
  (`Agent(subagent_type: "Explore")`), не сліпі повтори.
- **Готово, коли:** усі пункти задачі виконані й відмічені `[X]`, легасі старих
  механізмів прибрано, доки синхронізовані й звірені з кодом, усі зауваження
  код-рев'ю закриті, збірка обох архітектур зелена (+ тести, якщо застосовно),
  суміжні задачі оновлені.
